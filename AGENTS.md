When making edits:

- Every source file must begin with a short comment summarizing the file's purpose. Use the language's appropriate comment syntax. Generated files and formats that do not support comments are exempt.
- Source files whose primary export is a class or interface must use the same PascalCase name as that export; other source filenames use camelCase.
- Prioritize maintainability, readability, and architectural consistency over making the smallest possible change. When implementing a solution, consider the broader codebase and refactor or reorganize code as necessary to preserve a clean, modular, and scalable repository structure, while avoiding unnecessary complexity.

The goal is consistent, understandable code that is easy to maintain as the downloader and multimodal lecture-tutoring system evolve.
